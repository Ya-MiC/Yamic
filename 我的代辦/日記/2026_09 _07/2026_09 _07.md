# 2026-09-07

今天花了不少時間，把 Yamic 這個東西重新想了一遍。

一開始腦子裡一直繞著 Zorai、archify 這些現成的 Agent 專案打轉，想著要不要漢化、要不要接進去做引導面板。想到後面自己都覺得不對勁——那些東西是給懂 Agent、懂 API、懂 MCP 的人用的，介面全是模型、Token、Provider、Base URL。我要做的根本不是這個。

我要做的東西，是給完全不懂這些概念的人用的。他們不會關心背後是哪個模型、怎麼路由、花了多少 Token，他們只想說一句「幫我把這份問卷整理成報告」，然後拿到一份能用的檔案。

所以今天做的最重要的一件事，是把產品邊界砍掉一大半。

## 定位定下來了

Yamic 就是一個幫人把想法、資料、文件整理成「可用、可修改、可交付」成果的個人助手。不是 Agent 平台，不是開發者工具，是一個普通人打開就能用的軟體。

首頁不能像個控制台。使用者打開來，只該看到一句話：今天想完成什麼。下面頂多五個入口——整理文件、分析資料、寫正式文件、規劃一件事、匯出成果。模型、API Key、進階設定這些通通藏起來，不能第一眼就砸到使用者臉上。

## 砍掉 PPT

一開始還想著要不要做簡報功能，後來想通了：不做。

規劃、筆記這種東西交給 Markdown 就好，寫得清楚,結構好，讓有 Obsidian 的人直接在自己的 Vault 裡打開，看得到路徑、看得到連結，比我自己重造一個介面有意義多了。沒有 Obsidian 的人，就給一個最簡單的本地資料夾加閱讀介面，不勉強他裝軟體。

真正要保證做好的輸出，就兩種：Word、Excel、夠了，做多了也做不精。界面還是proton的docs那個精簡和漂亮
PDF。和docs/excel還有就是js/md這幾種導出方式我覺得足夠充足了


## 關於帳戶那件事

會員反向代理這個念頭，今天正式放棄了。風險太大，帳號會被封,使用者的登入資訊也不該交給我的軟體。有 API 的人自己接自己的，沒有的人，就老老實實走 OpenRouter 這種官方管道，設好額度上限，安全又清楚。

## 提醒自己

不要因為想讓它看起來很強大,就塞一堆功能進去。

先把最基本的一條路走順:使用者說一件事，看得到在做什麼，最後拿到一份真的能用的檔案。這件事做到穩、做到簡單、做到好看，比什麼都重要。

今天先到這裡，明天開始畫首次引導的流程圖。
