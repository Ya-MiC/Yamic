# 日記 · 2026年9月8日

今天看到 screenshottocode.com 這個開源專案(MIT License，GitHub 上 abi/screenshot-to-code，78k+ stars)，發現它的收費邏輯其實跟我一直在想的「湛箴」四面板服務(Docs + 試算表 + 文件管理 + AI 智能體協作整合)幾乎一模一樣。

## 觀察到的模式

代碼完全開源，MIT 授權，任何人都能 clone 下來自己部署、免費用。但官網託管版本要收費，原因不是鎖功能，而是:

1. 幫用戶省下申請/管理多個 AI 模型 API Key 的麻煩(Gemini、GPT、Claude、Replicate 都要接)。
2. 每次生成都要即時呼叫商業模型 API，這部分算力成本是真金白銀，作者要靠訂閱費覆蓋。
3. 免安裝、免配置 Docker/Playwright 的便利性本身就是可以賣錢的價值。

## 這是什麼收費方式

查了一下，這種「代碼完全公開、不閹割功能，收費收在託管便利性和算力成本轉嫁上」的模式，屬於 **COSS(商業化開源軟體)** 底下的一個分支，叫 **「自架免費 + 託管付費(Self-hosted vs. Managed Cloud)」**。

跟常見的「開源核心(Open Core)」不一樣 —— Open Core 是閹割社群版功能、把好功能鎖進付費版(像 GitLab CE/EE)；而我要走的路是**功能完全一致**，自架的人一分錢不用花，用我託管版本純粹是為了省事 + 我幫忙代跑 API 調用。代表案例：n8n、Supabase、Plausible。

## 對湛箴的啟發

這剛好印證了我原本的想法是對的方向:

- 保持「真開源、可自托管」——維持社群信任，也符合我一直堅持的「基於真正開源、可自架的方案再商業化」的原則。
- 定價分兩條腿走:
  - 按量計費：用戶可以選自己接 API Key，或用我託管的路由，抽 20% 左右的利潤。
  - 訂閱制：全球化低成本訂閱(大概 1.5 USDT/月，Stripe 支付)，把「省事」打包成固定月費，降低決策門檻。

這種組合既不違背開源精神，又能靠「代管便利性」和「算力代付費」兩個真實存在的成本/價值點撐起商業模式，是目前看到最適合湛箴的路線。接下來要想清楚:自架版和託管版之間的引導體驗要怎麼設計，才能讓新手用戶自然而然選擇付費託管，而不是覺得「反正開源我幹嘛付錢」。
