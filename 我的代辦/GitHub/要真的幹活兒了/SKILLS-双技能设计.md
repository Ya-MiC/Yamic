# 双 Skill 智能体设计：读书 × 女娲

> 核心命题：**先读懂一个人怎么思考，再替这个人动笔。**
> 读书 skill 负责「理解」，女娲 skill 负责「创作」。两者共享一份「思路画像」。

## 一、思路画像（Writing DNA）

读书 skill 的产物、女娲 skill 的输入。存为 JSON，持久化在本地：

```json
{
  "profile_id": "firm-001",
  "author": "某某会计师事务所",
  "language": ["zh-CN"],
  "structure": {
    "opening_style": "先结论后论证",
    "chapter_logic": ["概况", "风险识别", "数据分析", "审计意见", "附注"],
    "transition_habit": "用数据引出下一节，不用空泛过渡句"
  },
  "reasoning": {
    "evidence_chain": "准则条文 → 账面数据 → 交叉验证 → 结论",
    "risk_disclosure": "发现即披露，量化影响，给整改建议",
    "certainty_tone": "结论用确定性措辞，存疑事项单列"
  },
  "language_fingerprint": {
    "sentence_length": "短句为主，平均 25 字",
    "terminology": ["重要性水平", "实质性程序", "穿行测试"],
    "taboo": ["大概", "可能差不多", "应该没问题"],
    "number_format": "千元为单位，保留两位小数"
  },
  "exemplars": ["vector://chunk/12", "vector://chunk/47"]
}
```

这份画像**可视化展示给用户**——让人看到 AI 到底学到了什么，可以手动修正。
画像错了，生成一定错；画像可调，系统才可信。

## 二、读书 Skill（理解作者）

```
输入：历史文章（docx / pdf / xlsx，1 篇或 N 篇）
```

### 处理管线

1. **解析**：docx → 章节树；pdf 先走湛箴已有的 OCR 策略；xlsx → 表结构 + 表注
2. **切块**：按语义章节切（不按固定字数），每块带章节路径元数据
3. **三遍提取**（Prompt 链，每遍只干一件事，降低模型负担）：
   - 第一遍：篇章结构——各级标题怎么组织、顺序习惯是什么
   - 第二遍：论证逻辑——结论在哪出现、证据怎么摆、风险怎么披露
   - 第三遍：语言指纹——句式长短、高频术语、禁用词、数字格式
4. **入库**：原文切块进 sqlite-vec；提取结果合并成思路画像 JSON
5. **增量学习**：每上传新文章，画像做「增量更新」而非重建——写过的每篇报告都在让 AI 更懂你们

### 关键 Prompt 示例（第一遍）

```
你是文本结构分析器。阅读以下报告，只回答三个问题：
1. 全文的章节骨架是什么？（输出层级大纲）
2. 作者把最重要的结论放在哪里？开头、结尾还是分散各处？
3. 节与节之间是怎么衔接的？
不要总结内容，只描述结构。
```

## 三、女娲 Skill（按思路创作）

```
输入：写作任务（如「XX 公司 2026 年度审计报告」）+ 素材（底稿/数据）
```

### 生成管线

1. **检索**：任务描述 → 向量库取 Top-K 相似历史段落 + 加载思路画像
2. **思路大纲**（关键步骤）：**先输出大纲，不给正文。**
   大纲模仿画像中的 `structure.chapter_logic`，让用户确认「思路对不对」
3. **逐段成文**：用户在右侧 AI 面板逐段生成，每段可「重写 / 微调 / 通过」
4. **自检**：完稿后对照画像自查——术语是否一致、禁用词是否出现、
   风险披露是否完整、数字格式是否统一
5. **导出**：docx / xlsx 原生格式，排版遵循历史报告样式

### 为什么「先大纲后正文」

- 思路错了，正文写得再漂亮也是废稿——**在大纲阶段纠正，成本最低**
- 用户确认大纲的过程，本身就是在教 AI（确认/修改记录回流画像）
- 事务所场景下，报告结构需要合伙人把关，大纲正是把关的最小单元

## 四、双 Skill 的闭环

```
   上传历史文章          确认大纲/修改段落
        │                      │
        ▼                      ▼
   ┌─────────┐   画像更新   ┌─────────┐
   │ 读书     │ ◄───────── │ 女娲     │
   │ 理解思路 │            │ 按思路写 │
   └────┬────┘            └────┬────┘
        │                      │
        └──────► 思路画像 ◄─────┘
               （共同资产）
```

女娲 skill 的每一次用户修改，都是读书 skill 的新训练素材——
**用得越久，写得越像。这就是产品的护城河。**

## 五、多语言扩展

- 画像本身按语言分槽存储（`language` 字段），中文报告学中文思路，英文报告学英文思路
- 翻译不作为生成手段：先按母语思路成文，再用 Argos Translate（离线开源）或 LLM 整篇翻译，
  避免「翻译腔」污染语言指纹
- 英文客户报告：同一套管线，画像换成英文语料即可，无需改代码
