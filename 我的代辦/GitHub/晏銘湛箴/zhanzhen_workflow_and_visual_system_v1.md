# 湛箴（Zhanzhen）完整工作流與視覺系統

> 版本：v1.0  
> 用途：交給開發智能體、UI 智能體、測試智能體與演示影片智能體執行。  
> 核心定義：**湛箴是一個軟體；Docs、Sheets、OCR、AI 路由、Hermes 和四個面板共同構成同一個知識資產循環。**

---

# A. 產品的真正工作流

## A1. 湛箴解決的問題

使用者每天會產生聊天紀錄、課堂筆記、圖片、PDF、Excel、想法、會議結論與人工修改。但這些東西通常散落在聊天軟體、下載資料夾、筆記工具、雲端硬碟與腦中，最後無法被重用。

湛箴的工作不是替使用者「多寫一些內容」，而是完成這個閉環：

```text
注意力投入
  → 捕捉與保存
  → 人與 AI 共同整理
  → AI 自治推演
  → 人類最終判斷
  → 人工修正留下差分
  → 差分變成 SOP / 金標準 / 知識
  → 下一次工作時被重新調用
```

**湛箴的產品承諾：**

> 今天投入的注意力不會白費。它會被保存、整理、驗證、由人定奪，並在下一次工作時回到你手上。

---

## A2. 四個面板不是四道強制關卡

四個面板是四種工作狀態。使用者可按需要進入任意一個面板：

```text
                    ┌──────────────────┐
                    │ ① 人 + AI 共創   │
                    │ 整理、SOP、草稿  │
                    └────────┬─────────┘
                             │ 可選：建立議程包
                             ▼
                    ┌──────────────────┐
                    │ ② AI × AI 會議  │
                    │ 推演、反駁、驗證│
                    └────────┬─────────┘
                             │ 可選：提交人類決策
                             ▼
┌──────────────────┐ ┌──────────────────┐ ┌──────────────────┐
│ ③ 純人類議事     │◀│ ④ 修正與反哺     │▶│ SOP / 知識庫 /   │
│ 價值、判斷、拍板 │ │ diff、金標準、回寫│ │ 模板 / 下次調用   │
└──────────────────┘ └──────────────────┘ └──────────────────┘
```

允許的路徑例子：

- 使用者只想記日記：直接在①寫 Docs，保存即可。
- 使用者拿到一份 AI 報告：直接進④進行人工修正，不必先跑①②。
- 團隊要開重大決策會：直接進③，系統不得自動呼叫 AI。
- 使用者有 OCR 後的發票／報表：OCR 後直接建立 Sheet，再送到①或④。
- 使用者有一個複雜研究問題：①整理資料 → ②自治會議 → ③人類決策 → ④修正反哺。

**四面板的價值在於可追溯的關係，不在於要求每人走完所有步驟。**

## A3. 全局物件與資料關係

每個使用者都從「工作區」開始；每個工作區包含多個「專案」。所有內容都必須屬於一個專案，避免資料散落。

```text
帳戶 Account
└─ 工作區 Workspace
   └─ 專案 Project
      ├─ 文件 Document（Docs）
      ├─ 試算表 Spreadsheet（Sheets）
      ├─ 附件 Asset（圖片 / PDF / CSV / XLSX）
      ├─ OCR 任務 OCR Job
      ├─ SOP SOP
      ├─ 議程包 Agenda Pack
      ├─ AI 會議 Meeting
      ├─ 人類決策 Decision Record
      ├─ 修正差分 Diff
      ├─ 金標準 Golden Standard
      ├─ 知識條目 Knowledge Item
      └─ 匯出物 Export
```

### 所有物件共有的必要欄位

```text
id                 全域唯一 ID
workspace_id       所屬工作區
project_id         所屬專案
created_at         建立時間
updated_at         最後更新時間
created_by         建立者（人類或 Agent）
origin_panel       首次產生於哪個面板（1 / 2 / 3 / 4）
source_refs        來源物件 ID 清單
version            版本號
visibility         private / workspace / shared
ai_status          no_ai / ai_draft / human_verified
```

其中 `ai_status` 非常重要：

- `no_ai`：完全未經 AI 處理，例如第三面板人類原始發言。
- `ai_draft`：AI 產出或 AI 協助整理，尚未被人確認。
- `human_verified`：人類在第四面板確認、修改或定稿。

# B. 使用者工作流

## B1. 第一次啟動與新手引導

### 目標

讓完全不會 Docker、Python、OCR、API 或 Agent 的使用者，在三分鐘內理解：

1. 我的資料存在哪裡。
2. 我可以寫文件與表格。
3. OCR 和 AI 是可選能力，不強迫設定。
4. 四面板是自由工作流，不是複雜規則。

### 第一次啟動流程

```text
安裝 ZhanzhenSetup.exe
  ↓
歡迎頁：一句話介紹「把注意力沉澱為資產」
  ↓
選擇資料儲存位置
  預設：%LOCALAPPDATA%\Zhanzhen\data\
  可選：D:\ZhanzhenData\
  ↓
OCR 選擇頁
  [安裝免費本地 OCR] [使用湛箴雲端 OCR] [暫時跳過]
  ↓
AI 路由選擇頁
  [先不用 AI] [填自己的 API] [使用湛箴代管路由]
  ↓
建立第一個示範專案「我的第一個湛箴專案」
  ↓
互動導覽：建立 Docs → 匯入圖片 → OCR → 建立 SOP → 看見 diff
  ↓
進入主畫面
```

### 新手引導的固定文案

- 資料位置頁：
  > 你的資料先保存在自己的電腦中。你隨時可在設定中開啟資料夾、建立備份或改到其他磁碟。

- 本地 OCR 頁：
  > 本地 OCR 免費，資料不會上傳，但第一次下載模型且速度可能取決於你的電腦。你可以隨時跳過。

- 代管路由頁：
  > 湛箴會在送出前顯示預估費用。你也可以隨時改用自己的 API，不被綁定。

- 四面板頁：
  > 四個面板是四種工作方式，不是必經步驟。從你現在最需要的地方開始即可。

## B2. 日常記錄工作流：最核心、每天都要能用

### 使用者動作

```text
打開湛箴
  ↓
按「＋ 新建」
  ↓
選擇：文件 / 試算表 / 匯入檔案 / OCR 掃描
  ↓
選擇要放入的面板（預設①共創，但可跳過）
  ↓
輸入或貼上內容
  ↓
自動本地保存
  ↓
可選：整理為 SOP / 送進 AI 會議 / 人類討論 / 人工修正
```

### 系統行為

1. 按鍵停止 800 毫秒後，保存本地文件快照。
2. 狀態列顯示「已保存到本機」；如果已登入並同步成功，顯示「已同步」。
3. 不在使用者未要求時彈出 AI 建議，避免消耗注意力。
4. 每篇內容自動記錄建立時間、最後修改時間與面板來源。
5. 使用者可按 `Ctrl + K` 搜尋所有專案、文件、表格、SOP 和會議結論。

### 產品底線

**「打開即寫、寫完即存」必須在沒有網路、沒有 AI、沒有帳戶、沒有付費的情況下成立。**

## B3. OCR 工作流

### 輸入

- 圖片：PNG、JPG、WEBP
- 文件：PDF
- 表格：圖片、掃描 PDF、CSV、XLSX

### 使用者流程

```text
拖曳圖片 / PDF 進湛箴
  ↓
系統辨識檔案類型
  ↓
使用者選擇：
  [本地 PaddleOCR：免費，可能較慢]
  [湛箴雲端 OCR：顯示預估點數]
  [只當附件，不辨識]
  ↓
OCR 完成後預覽結果
  ↓
使用者選擇：
  [插入文件]
  [建立試算表]
  [只保存 OCR 文字]
  [進入第四面板人工校正]
```

### OCR 的輸出必須包括

```text
原始附件
OCR 純文字
OCR 區塊座標（供點擊回原圖）
表格結構（列、欄、儲存格）
引擎名稱、模型版本、執行時間
可信度分數
人工校正版本（若有）
```

### OCR 導入四面板

- ①：把 OCR 結果整理為報告、筆記或 SOP。
- ②：把 OCR 資料作為自治會議的證據來源。
- ③：允許人類引用 OCR 結果，但不允許 AI 介入處理。
- ④：人工校正 OCR 錯字、欄位、數字；修正後可設為對應類型的金標準。

## B4. 面板 ①：人 + AI 共創工作流

### 使用者目的

把零散素材變成可用的工作成果：文件初稿、SOP、流程圖、資料表、分析問題。

### 進入條件

使用者可從空白文件、OCR 結果、匯入 Sheet、已有筆記，或第二面板會議結論進入。

### 使用者操作

```text
選中一段文字／一個表格／多個附件
  ↓
選擇 AI 任務：
[摘要] [整理為 SOP] [產生 Mermaid] [找出缺失資料]
[轉成表格] [建立會議議程] [自訂提示]
  ↓
確認模型路由和預估費用（代管路由時）
  ↓
AI 產生「草稿區塊」，不直接覆蓋原稿
  ↓
使用者選擇：
[插入文件] [替換選取內容] [送往第二面板] [丟棄]
```

### 系統輸出

- SOP：名稱、目的、輸入、步驟、判斷條件、輸出、責任人、版本。
- Mermaid：以程式碼區塊保存，並可視覺預覽。
- 議程包：問題、背景、可用資料、代理角色、預期輸出、限制條件。
- AI 草稿：必須帶上來源與模型資訊。

### 禁止行為

- 不得默默改寫使用者原文。
- 不得把 AI 草稿標成「人類已確認」。
- 不得把使用者資料送去未被選定的 AI provider。

## B5. 面板 ②：AI × AI 自治會議工作流

### 使用者目的

使用者不想親自參加重複、耗神的前期推演；讓多個有明確職責的 Agent 對同一個議題進行有限、可追溯、可中止的討論，產出供人審閱的草稿。

### 建立會議

```text
來自：①的議程包 / 手動新建 / 某份文件或試算表
  ↓
設定：
- 議題
- 可讀取的證據與附件
- 代理角色
- 每個角色可處理的領域
- 最多輪數
- 預算上限
- 停止條件
  ↓
按「開始自治會議」
  ↓
Hermes 在本機編排 Agent 輪次，透過選定路由調模型
  ↓
逐句展示會議；使用者隨時可暫停、終止或補充證據
  ↓
產出結構化會議報告
```

### 第一版固定代理角色

先不用讓使用者自定義無限角色；第一版固定四個角色，以確保品質與可測試性：

| 代理 | 責任 | 不能做什麼 |
|---|---|---|
| 問題拆解員 | 澄清問題、定義輸入與假設 | 不得下最終結論 |
| 證據審查員 | 檢查來源、標出證據不足 | 不得捏造來源 |
| 分析推演員 | 根據資料提出方案、表格、計算邏輯 | 不得越過資料限制 |
| 反方審查員 | 尋找漏洞、反例、風險與未驗證假設 | 不得為反對而套話 |

### 會議協議（必須寫入程式）

```text
規則 1：一人一句。
每名代理每一輪最多輸出一個完整主張；主張字數上限由系統配置。

規則 2：無證據即標假設。
沒有來自來源物件、計算或可追溯常識的說法，標記為「假設」。

規則 3：領域不得越界。
角色只處理自己被授權的領域；越界時必須要求其他角色補充。

規則 4：禁止套話。
若輸出只含空泛同意、重複先前內容或無可驗證新增資訊，判為無效輪次。

規則 5：人類不在場不代表 AI 可拍板。
會議結論一律是「建議」或「待決事項」，不是最終決策。

規則 6：預算與輪數有限。
達到上限、達到共識、證據不足或使用者停止時，會議立即結束。
```

### 會議輸出格式

```text
1. 問題與範圍
2. 已使用證據清單
3. 已達成的共識
4. 有分歧的觀點
5. 未驗證假設
6. 風險與反例
7. 建議的人類決策選項
8. 待補資料
9. 產出的 Docs / Sheet / Mermaid
10. 模型、成本、輪數、時間與完整記錄連結
```

### 後續去向

- `送往③`：交由人類討論、投票與定奪。
- `送往④`：人類直接修正 AI 報告，建立金標準。
- `存入專案`：暫存，日後再處理。

## B6. 面板 ③：純人類議事工作流

### 這個面板的意義

人類需要保留一個絕對不被 AI 影響、提示、補全或代言的地方，處理價值取捨、責任歸屬、重大選擇與真正的共識。

### 系統級限制

當使用者開啟③時，前端與後端同時進入 `HUMAN_ONLY` 模式：

```text
禁止 API：LLM、OCR、AI 摘要、Agent、提示建議、自動分類。
禁止 UI：AI 按鈕、魔杖圖示、生成按鈕、推薦文字、AI 通知。
允許能力：文字、表格、附件、投票、引用、手動匯出、簽名。
```

### 使用者流程

```text
建立人類議事室
  ↓
邀請人類參與者（Email / 帳戶 ID）
  ↓
設定：議題、閱讀資料、截止時間、投票規則
  ↓
人類發言、引用資料、撰寫決策草案
  ↓
發起投票或確認結論
  ↓
每名確認者用本機私鑰簽名
  ↓
生成不可被 AI 偽裝的 Decision Record
```

### 簽章資料

```text
決策 ID
決策正文的雜湊值
簽名者帳戶 ID
簽名者公鑰 ID
簽名時間
Ed25519 簽名值
```

AI 可以在其他面板產生資料；但任何內容進入③後，都必須保留來源標籤，且不由 AI 自動解釋。

## B7. 面板 ④：人工修正與反哺工作流

### 使用者目的

把「AI 產物被人改過」這件事，從一次性修補變成可累積的訓練資料、SOP 改進與可重用範本。

### 使用者流程

```text
打開 AI 草稿 / OCR 結果 / AI 會議報告
  ↓
進入④修正與反哺
  ↓
左側：原始版本
右側：人工可編輯版本
中間：diff（新增 / 刪除 / 修改）
  ↓
使用者為重要修正補充原因：
[事實錯誤] [格式不符] [推理跳躍] [遺漏條件]
[語氣問題] [資料錯位] [人類價值判斷]
  ↓
確認修正
  ↓
選擇回寫範圍：
[只保存本專案] [更新我的 SOP] [建立金標準]
[加入團隊知識庫（需權限）]
  ↓
系統建立新版本、差分、關聯與索引
```

### 必須保留的差分資料

```text
source_object_id       原始 AI / OCR 物件
human_revision_id      人工版本
before_content         修改前內容
after_content          修改後內容
diff_type              add / delete / replace / cell_change
reason_code            修正原因
reason_note            人工補充說明
reviewer_id            修正人
scope                  project / personal / team
approved_at            確認時間
```

### 反哺不是「自動拿去訓練模型」

第一版的反哺方式是**檢索與提示詞層面的改進**：

```text
下一次相似任務發生
  ↓
Hermes 搜尋：同類 SOP、已確認金標準、相似 diff
  ↓
把相關規則作為受控上下文提供給模型
  ↓
模型生成更接近人類標準的草稿
```

不得在使用者不知情的情況下把私人資料拿去微調外部模型。若未來提供微調服務，必須使用獨立、明確同意、可撤回的設定。

# C. 軟體內部工作流

## C1. 本地優先資料流

```text
使用者輸入
  ↓
Tauri 桌面端
  ↓
本地 SQLite + 專案檔案夾（立即保存）
  ↓
使用者是否登入並開啟同步？
  ├─ 否：僅留本機；所有基本 Docs / Sheet 照常使用
  └─ 是：變更進入同步佇列
          ↓
       雲端 API 驗證帳戶與權限
          ↓
       PostgreSQL 記錄 metadata；S3 儲存附件／快照
          ↓
       客戶端收到同步成功狀態
```

### 資料存放位置

```text
%LOCALAPPDATA%\Zhanzhen\
├─ data\zhanzhen.db
├─ data\projects\{project_id}\docs\
├─ data\projects\{project_id}\sheets\
├─ data\projects\{project_id}\assets\
├─ data\projects\{project_id}\ocr\
├─ data\projects\{project_id}\meetings\
├─ data\projects\{project_id}\exports\
├─ config\settings.json
├─ config\routes.json
├─ backups\
└─ logs\
```

API Key 不得存於 `routes.json` 明文；僅保存 provider、模型與路由設定。實際密鑰使用 Windows Credential Manager 儲存。

## C2. AI 路由資料流

```text
使用者按下 AI 任務
  ↓
前端顯示：模型、是否上傳資料、預估 token／費用
  ↓
使用者確認
  ↓
路由設定？
  ├─ 自訂 API（BYOK）
  │   ↓
  │   以使用者本機憑證庫的 key 直接呼叫其 endpoint
  │   ↓
  │   回傳結果，保存到本地草稿
  │
  └─ 湛箴代管路由
      ↓
      桌面端向湛箴 API 取得短效 router token
      ↓
      Zhanzhen Router 檢查：會員狀態、餘額、模型可用性、風險限制
      ↓
      Router 呼叫 OpenRouter / OCR Provider
      ↓
      保存：供應商成本、用戶扣款、模型、token、時間、任務 ID
      ↓
      回傳結果，保存為 ai_draft，不覆蓋原文
```

### 路由收費規則

```text
使用者自訂 API：湛箴不從模型費賺取差價。
```

## C3. Hermes 自治會議資料流

```text
議程包 + 指定證據 + 角色 + 預算
  ↓
Hermes Meeting Orchestrator（本機）
  ↓
載入會議協議與角色邊界
  ↓
Round 1：問題拆解員一句
  ↓
Round 1：證據審查員一句
  ↓
Round 1：分析推演員一句
  ↓
Round 1：反方審查員一句
  ↓
規則驗證器：是否有證據？是否套話？是否越界？是否到預算？
  ↓
下一輪或停止
  ↓
輸出：共識報告 + 未決問題 + Sheet / Docs 草稿 + 完整日誌
```

### Hermes 對檔案的權限

| 能力 | 預設狀態 | 說明 |
|---|---|---|
| 讀取指定專案資料 | 使用者授權後允許 | 僅讀取議程包引用的內容 |
| 寫入 AI 草稿 | 允許 | 只能寫入草稿／會議輸出區 |
| 覆蓋人類文件 | 永遠禁止 | 必須透過④由人確認 |
| 上傳至 AI provider | 每次任務明示 | 顯示 provider、內容範圍和預估費用 |
| 讀取第三面板內容 | 永遠禁止 | HUMAN_ONLY 隔離 |
| 對外發送 Email／訊息 | 永遠禁止 | 未來若加入也要逐次確認 |

## D1. 不可改變的核心色

湛箴唯一的核心色系：

```text

深灰紫（基底）     #594C57
```

## D4. 四面板如何區分，而不破壞色系

四個面板**不用四種高飽和顏色**，採「同一配色 + 不同符號 + 不同邊框節奏」：

| 面板 | 圖示語義 | Light 的選中樣式 | Dark 的選中樣式 |
|---|---|---|---|
| ① 共創 | 對話泡泡 + 鉛筆 | 藕粉底色 + 左側 3px 深灰紫線 | 低飽和藕粉底色 + 淺薄荷圖示 |
| ② 自治會議 | 四個相連節點 | 淺薄荷底色 + 深灰紫圖示 | 深灰紫卡片 + 藕粉節點圖示 |
| ③ 人類議事 | 人形 + 簽章筆 | 白底 + 雙線深灰紫邊框 + `Human only` 標籤 | 深色底 + 淺薄荷細邊框；絕不顯示 AI 圖示 |
| ④ 修正反哺 | 兩頁文件 + diff 線 | 藕粉細框 + 修改標記；新增使用薄荷、刪除使用灰紫刪除線 | 灰紫底 + 藕粉框；diff 仍不用紅綠對立 |

### Diff 顏色規則

為符合色盲可用性與「不使用紅色」偏好：

```text
新增：淺薄荷底 + 「＋」符號
刪除：淡灰紫底 + 刪除線 + 「－」符號
修改：淡藕粉底 + 「↔」符號
不依賴顏色；所有變更必須有文字／圖示標記。
```

## D5. 設計語言規則

- 圓角：12px 卡片、8px 輸入框；不使用過度軟萌的大圓角。
- 字體：優先系統字體；中文可採 Noto Sans TC / Noto Sans SC 作為 Web fallback。
- 行高：正文至少 1.65；避免高密度擠壓。
- 陰影：只有彈窗、浮動選單使用極淡陰影；文件畫布不漂浮。
- 動畫：150–200ms 淡入與位置過渡；不使用炫目的粒子、漸層光效。
- 圖示：線性、幾何、克制；湛箴品牌可延伸為「碎片化但有秩序的幾何信任符號」。

# G. 演示影片工作流（交給影片智能體）

## G1. 90 秒產品演示腳本

### 0–8 秒：痛點

畫面：桌面上散落聊天紀錄、PDF、圖片、Excel、下載檔案夾；使用者打字後關掉視窗。

旁白：

> 每天寫下很多東西，最後卻找不到、用不上。注意力，是最容易流失的資產。

### 8–18 秒：湛箴出現

畫面：打開湛箴，淺薄荷背景、藕粉選中項、深灰紫文字；建立「市場研究」專案。

旁白：

> 湛箴，把你的文件、表格、資料與判斷，放進一個可重用的知識循環。

### 18–34 秒：① 共創

畫面：拖入 PDF 截圖 → 選本地 OCR → 結果插入 Docs → 按「整理為 SOP」→ Mermaid 預覽。

旁白：

> 在共創面板，你和 AI 把零散素材整理成 SOP、初稿與流程圖。AI 的內容始終是草稿，由你決定是否採用。

### 34–50 秒：② 自治會議

畫面：點「建立會議議程」→ 四個代理逐句發言 → 證據標記 → 生成結構化報告與 Sheet。

旁白：

> 在自治會議，Hermes 依照一人一句、要有證據、不得越界的規則進行推演，替你完成前期分析。

### 50–64 秒：③ 純人類議事

畫面：切換至石墨深灰紫的人類議事區；畫面無 AI 圖示；多人投票與簽名。

旁白：

> 但重要判斷，永遠保留給人。人類議事區完全不注入 AI，讓真正的價值選擇由人做出。

### 64–78 秒：④ 修正反哺

畫面：左右 diff；新增為薄荷、修改為藕粉；選「建立金標準」「回寫 SOP」。

旁白：

> 你每次修正 AI，不只是改完一次。湛箴保存差分，建立金標準，讓下一次的工作更接近你的標準。

### 78–90 秒：商業與結尾

畫面：設定 → 自訂 API 或湛箴代管路由；本地資料位置；會員方案。

旁白：

> 本地優先、自訂路由、按量透明。湛箴，讓注意力成為可以累積的資產。

畫面文字：

> 湛箴 Zhanzhen  
> Focus becomes assets. Human judgment remains final.

# H. 最終驗收：湛箴是否真的成立

在支付、雲端同步、全球推廣之前，先拿以下真實測試驗收：

1. 使用者能否離線打開湛箴、三秒內新建文件、一天後仍找到內容？
2. 使用者是否能從一張圖片得到 OCR 文字或表格，並知道結果與原檔在哪裡？
3. 使用者是否能從一份筆記產生 SOP，且 AI 不會偷偷改掉原文？
4. 一場 AI 會議是否能被人讀懂、查證、暫停，且能清楚區分「證據」與「假設」？
5. 第三面板是否在技術與視覺上都真正沒有 AI？
6. 第四面板是否能讓人工修正變為下次可利用的金標準，而非被遺忘？
7. 使用者是否在任何時候都知道：資料在哪裡、AI 是否被呼叫、用了哪個模型、花了多少錢？

這七項全成立，湛箴才不是概念，而是一個值得用戶每月付費的軟體。
